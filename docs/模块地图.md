# 模块地图与扩展指南

给"要动这个项目的人"看的一页纸：**东西在哪、数据怎么流、加功能该动哪几个文件**。

配套文档：[参数与版本管理](参数与版本管理.md)（版本怎么升、参数放哪层）。

---

## 一、分层

依赖方向**严格单向向下**，不允许下层反向依赖上层：

```
        ui/            界面：Compose 页面 + ViewModel（只做展示与交互编排）
         │
      data/repo/       业务编排：一次对话/一次提炼的完整流程
         │
 ┌───────┼────────┬──────────────┐
 │       │        │              │
data/db  remote/  core/memory/  media|tts|modules|pet
 存储     传输     纯计算          平台能力
 │       │        │              │
 └───────┴────────┴──────────────┘
         core/      基础：Result / JsonExt / 时间工具
```

三条硬规则：

1. **`core/` 不依赖 Android**（除时间工具外），因此可以纯 JVM 单测。
   `MemoryDecay`、`MemoryRecall`、`MemoryTextIndex`、`ExtractedMemory` 都是纯函数对象——
   这是记忆系统能被 207 个用例钉住的前提。
2. **`remote/` 只负责"把字节搬过去、把字节搬回来"**，不做业务判断。
   解析全部抽成纯函数（`ChatStreamParser`、`SearchResponseParser`），单独测。
3. **`ui/` 不直接碰网络或 SQL**，一律经 `AppContainer` 拿到的 repo / store。

### 2.1 导航与"角色即会话"

**一个角色固定对应一段对话**，所以导航上只有两层喵：

```
首页（角色列表，微信式）
   ├─ 点一行 ──▶ 该角色的对话 ──▶ 返回键回列表
   ├─ 收藏 / 记忆 / 设置   （底部另外三个标签）
   └─ 搜索 / 模块 / 调试   （二级页，AppScreen）
```

没有"新建对话 / 切换对话"这一层喵：

- 角色列表由 `ConversationRepository.chatList()` 产出（角色 × 它那段对话），
  排序纯函数 `buildChatList` 有单测钉住
- 对话在进入时才由 `ChatEngine.openConversation()` 建出（有开场白就一并写入），
  所以"没聊过的角色"在列表里 `conversation == null`，不需要凭空建空对话
- 删除角色走 `ChatViewModel.deletePersona()`，会话/消息/记忆/索引由
  `PersonaStore.delete` 连带清理
- 对话标题 = 角色名（创建时定下），不再拿首条消息改写

> **改这一块要特别小心**：角色列表有两份来源（`ChatViewModel.chatList` 与
> `PersonasViewModel.personas`）。早期"新建角色后看不到"的 bug 就是
> 只有角色页刷新、首页那份没刷新造成的。任何改动角色的事件都必须让两边都重算喵。

## 三、一次对话发生了什么（数据流）

这是全项目最长的链路，读懂它，其余都是它的子集。

```
用户点发送
   │
   ▼
ChatViewModel.send()
   │
   ▼
ChatEngine.generate()                                  ← data/repo/ChatEngine.kt
   │
   ├─ 1. 落库用户消息（Stores.MessageStore）
   │
   ├─ 2. 联网（可选）：SearchClient → SearchResponseParser → List<SearchHit>
   │
   ├─ 3. 记忆准备：MemoryDirector.prepare()             ← 全本地、确定性
   │        ├─ advanceTurn()            推进轮次
   │        ├─ applyDecay()             按天衰减；跌破剪枝阈值就地压成残影
   │        ├─ recallFor()              粗召回 → 多因子打分 → 冷却/淡忘/概率 → 唤醒
   │        └─ markRecalled()           给唤醒的刷新冷却起点
   │
   ├─ 4. PromptBuilder.turns()          人设 + 记忆 + 历史 + 联网资料 → 请求体
   │
   ├─ 5. PromptRefiner.refine()（可选）  小模型润色；超时/异常即用原生提示词
   │
   ├─ 6. ChatClient.stream()            SSE 传输
   │        └─ ChatStreamParser        逐 chunk 解析（在此拦住 JSON null 噪音）
   │
   ├─ 7. BurstAccumulator              按空行拆成多条短消息，每段只落库一次
   │
   ├─ 8. 落库助手消息
   │
   └─ 9. 收尾（异步、不阻塞回复）
            ├─ MemoryExtractionService.launchAsync()      提炼新记忆
            └─ MemoryExtractionService.launchPruneCompression()  优化剪枝残影
```

**关键设计：第 9 步用 `AppContainer.appScope` 而不是调用方的协程。**
用户可能一发完消息就退出聊天页，但"替用户记住这件事"不该跟着界面一起消失。

## 四、扩展指南：加功能该动哪

### 4.1 加一个设置项

见[参数与版本管理 §4.1](参数与版本管理.md)——四处齐改，漏一处就静默失效。

**参数要挂「?」说明**：`ui/settings/HelpTexts.kt` 里加一条 `HelpContent`，
然后把它传给控件的 `help =` 参数。共享控件已经内置支持，不必自己画问号：

| 控件 | 写法 |
| --- | --- |
| `SwitchRow` / `SliderRow` | 多传一个 `help = HelpTexts.xxx` |
| 输入框 | `label = { LabelWithHelp("标签", HelpTexts.xxx) }` |
| 整组小标题 | `RowLabelWithHelp(label = "…", content = HelpTexts.xxx)` |
| 自定义布局 | 直接放 `HelpDot(content = HelpTexts.xxx)` |

说明按「用法 / 调整影响 / 建议参数」三段写，三段都可留空、留空的段不会渲染。
三段全空时问号不显示，所以可以无条件挂上。

> 「调整影响」这一段最值得花时间：用户看得懂"这是什么"，但通常不知道
> "调大了会怎样"。写清后果比解释原理有用。

### 4.2 加一张表 / 一个 Store

1. `DbHelper.createXxx(db)` 建表（含索引），并在 `onCreate` 里调用
2. `Db.VERSION +1`，在 `onUpgrade` 补一个 `if (oldVersion < N)` 分支，**并让 `onCreate` 与
   `onUpgrade` 建出完全一致的结构**
3. `Stores.kt` 里加 `XxxStore`，在 `QingYuDatabase` 上暴露为属性
4. 若表是给记忆用的，考虑是否需要在升级时**回填**（参考 `backfillMemoryIndex`）
5. 实体加到 `data/Models.kt`，配上 `toValues()` / `toXxx()` 双向映射

> 反序列化（`toXxx`）必须容忍缺列与 `null`，因为老库升级上来的行可能是默认值。

### 4.3 加一个页面

1. `ui/vm/XxxViewModel.kt`：`AndroidViewModel` + `AppContainer.get(application)` +
   `companion object { fun factory(application) }`（照抄 `ShellViewModel`）
2. `ui/vm/XxxUiState.kt`（简单的可直接写进 ViewModel 文件）
3. `ui/xxx/XxxScreen.kt`：只读 `state`、只调 `viewModel.xxx()`，不碰网络与 SQL
4. 若要成为底部标签 → `QingYuAppRoot.kt` 的 `HomeTab` 加枚举 + `when` 分支
5. 若是二级页 → `ui/vm/ShellViewModel.kt` 的 `AppScreen` 加 `data object` + `navigate()`

### 4.4 加一类外部能力（新的"另一个 OpenAI 兼容接口"）

项目已有识图 / 语音 / 搜索三例，第四例照这个形状做：

1. `data/ApiConfig.kt` 加路径常量与地址补全分支
2. `remote/XxxClient.kt`：只做传输，鉴权用统一的 Bearer
3. `remote/XxxParser.kt`：**把所有解析抽成纯函数**（这是能被测试的前提）
4. `remote/XxxPayload.kt`：请求体构造，也抽成纯函数
5. `AppContainer` 里装配
6. `Settings` 加配置（四处齐改）+ 设置页加"测试"按钮
7. `app/src/test/` 补解析与请求体的用例——**这类"输入不受我们控制"的地方必须有测试**

### 4.5 加一种记忆类型

1. `data/Models.kt` 的 `MemoryCategory` 枚举加常量（**枚举名会落库**，之后不能改名）
2. `core/memory/MemoryDecay.kt` 若涉及衰减/唤醒差异 → 加系数并在 `MemoryDecayTest` 钉一条
3. `core/memory/MemoryRecall.kt` 若涉及召回 → 改 `RecallConfig` 或候选池过滤
4. `MemoryExtractionService.INSTRUCTION` 里告诉模型何时产出该类型
5. `ui/memory/MemoryScreen.kt` 的筛选与展示
6. 补测试

### 4.6 给 JS 模块加一个宿主 API

1. `modules/ModuleManager.kt` 里注册 `qingyu.xxx`
2. **必须走白名单接口**：没有网络、没有文件、没有反射、拿不到 Context——
   沙箱是结构性的，不是靠运行时检查
3. 单次运行有 2 秒与指令数上限，新 API 若是耗时的，自己也要有界
4. `SimpleJsEngineTest` 补用例

## 五、约定（写新代码时照这个来）

- **注释**：每个文件、每个类/对象顶部一段 KDoc，说"它是什么、为什么这样设计"，
  而不只是复述代码。**为什么这么写要写进注释**（例：为什么 `NEVER_RECALLED_TURN` 是 `-100`
  而不是 `0`），这是这个项目注释的主要价值。
- **命名**：`XxxStore`（DAO）、`XxxClient`（传输）、`XxxParser`（纯函数解析）、
  `XxxViewModel` + `XxxUiState`（界面）、`XxxConfig`（参数集合）。
- **纯函数优先**：能写成纯函数的（解析、打分、衰减、拆条）就不要掺协程与 Android 依赖，
  这样才测得动。
- **确定性**：记忆的"想不想得起来"必须可复现——随机数按 `(记忆 id, 轮次)` 播种
  （见 `MemoryRecall.Dice`），同输入永远同结果。**不要引入全局随机源。**
- **失败要静默降级**：润色超时 → 用原生提示词；AI 语音失败 → 回退系统 TTS；
  提炼失败 → 忽略。**这些能力都是纯收益项，不值得拖住主流程。**
- **测试取向**：只给"输入不受控制"或"错了不报错、只会静默失效"的地方写测试，
  不追求覆盖率数字。README「三处静默失效的陷阱」一节列了具体清单。

## 六、测试布局

```
app/src/test/java/com/qingyu/app/
├── core/memory/   MemoryDecayTest、MemoryRecallTest、MemoryTextIndexTest、
│                  MemoryTripleValidatorTest、BioRhythmTest、PromptRefinerTest、UtilityLlmRouterTest
├── data/          ApiEndpointTest、ChatImportParserTest、BurstAccumulatorTest、ImageTurnMatcherTest
├── media/         ImageScalingTest
├── modules/       SimpleJsEngineTest
└── remote/        ChatPayloadTest、ChatStreamParserTest、SearchResponseParserTest
```

**16 个测试类 / 207 个用例**，全部是纯 JVM 测试（不需要模拟器）。

跑测试：

```powershell
$env:JAVA_HOME = 'F:\app\jbr'
.\gradlew.bat :app:testDebugUnitTest
```

测试类路径特意依赖了真实的 `org.json`（`testImplementation(libs.json)`）——
Android 单元测试里的 `org.json` 是空壳，调用会抛 "not mocked"，而协议解析正是靠它做的。
**不要删掉这个测试依赖。**
